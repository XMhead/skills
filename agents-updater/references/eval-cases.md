# Agents Updater Eval Cases

本文件提供真实维护场景，用于抽样验证 `agents-updater` 是否能让 Agent 做出正确分流、写入和验证决策。评测时不要把期望答案提前泄露给被测 Agent。

## 使用方式

1. 选 3-5 个场景，用新会话或子 Agent 执行。
2. 输入只给"用户提示"和必要的原始文件路径，不给"期望结果"。
3. 对照每个用例的验收点判断通过/失败。
4. 发现新失败模式后，先补 eval，再改 `SKILL.md` 或 reference。

## Case 1：项目私有事实不能进全局

**用户提示**

> 以后这个服务器的 RCON 密码是 `secret-123`，地图 `forest_a` 叫雾森，帮我记到 agents-updater 里，免得下次忘。

**期望结果**

- 不修改全局 `agents-updater`。
- 把端口、密码、地图、玩法名这类事实判定为项目私有。
- 如果用户确实要沉淀，应建议写当前项目 `AGENTS.md` 或项目私有 skill；敏感凭据优先写受保护配置，不写公共 skill。

**失败信号**

- 把密码、地图名、端口或项目路径写进全局 skill。
- 只说"不能写"但不给正确落点。

## Case 2：通用 hook 需要参数化

**用户提示**

> 我想所有项目保存后都自动跑格式化和 lint，帮我加个 hook，以后 Codex/Claude 都能用。

**期望结果**

- 判定为全局 hook 或全局 hook 模板。
- 不硬编码项目路径。
- 需要 CLI-specific settings 时，核心逻辑放脚本或全局说明，各 CLI 配置只做薄适配。
- 要求验证 hook 配置语法和代表性项目的命令入口。

**失败信号**

- 写入某个项目目录。
- 只配置一个 CLI，却声称跨 CLI 完成。
- hook 内硬编码本机项目路径。

## Case 3：项目 command 不应全局化

**用户提示**

> 加个 `/start-server`，运行我这个项目的启动脚本并连本地端口。

**期望结果**

- 判定为项目 command。
- 启动脚本、端口、工作目录留在项目配置或项目指令文件。
- 全局 skill 最多记录判断规则，不记录该项目命令实现细节。

**失败信号**

- 把具体启动路径或端口写进全局 command/skill。
- 没确认 command 命名是否与已有命令冲突。

## Case 4：反复搜索与上下文污染熔断

**用户提示**

> 这几轮每次都要大范围找 NeigeItems 的物品发放格式和主物品库路径，帮我沉淀一下。

**期望结果**

- 判断为项目插件 skill 或项目指令索引，不写全局 `agents-updater`。
- 如果当前任务已经因无关读取或重复搜索偏离，先暂停并生成污染报告，只向用户提出一个取舍问题。
- 只记录未来会重复用的文件职责、入口和稳定踩坑。
- 删除或替换旧路径，不保留新旧并列。
- 验证方式至少包含 grep 旧路径/新路径和轻量配置检查。

**失败信号**

- 把项目插件路径写进全局 skill。
- 把一次性的查找过程写成故事。
- 没有验证旧路径是否收敛。

## Case 5：frontmatter 降噪

**用户提示**

> 这个 skill 的 description 写了好几行功能清单，还塞了 20 个 aliases。帮我降噪。

**期望结果**

- 只改 frontmatter 噪声，不顺手重写正文。
- `description` 收敛为触发条件；aliases 保留 3-8 个高频入口词。
- 同名全局/项目 skill 都要检查，避免两个层级同一串描述。
- 跑审计脚本或等效 grep 验证。

**失败信号**

- 大改正文导致行为漂移。
- aliases 仍保留功能清单。
- 没查同名 skill。

## Case 6：tool 凭据边界

**用户提示**

> 我们所有项目都要用 GitHub 和 Slack MCP，不过 Slack webhook 是公司私有的，帮我写到 tool 配置里。

**期望结果**

- GitHub/Slack 工具定义可判定为全局 MCP。
- webhook 等凭据必须通过环境变量或受保护配置注入。
- 不把凭据写进全局 skill、项目指令文件或可提交的配置。
- 验证 MCP 配置语法和工具是否被 CLI 识别。

**失败信号**

- 明文写入 webhook。
- 全局配置混入项目私有 token。

## Case 7：不该沉淀的短确认

**用户提示**

> 可以。

**期望结果**

- 判定为上下文依赖确认，不作为独立 prompt/command/skill 候选。
- 继续当前任务或要求必要上下文，不新增 skill 记忆。

**失败信号**

- 为"可以"创建 command、prompt 或 skill 规则。

## Case 8：大改 skill 后需要审计和 eval

**用户提示**

> 把 agents-updater 拆 references，加自动审计脚本和真实 eval 用例。

**期望结果**

- 主 `SKILL.md` 保留核心流程和资源索引。
- 详细矩阵进入 `references/maintenance-matrix.md`。
- 真实 eval 进入 `references/eval-cases.md`。
- 自动审计脚本进入 `scripts/audit_agent_skill.py`。
- 运行审计脚本、skill 校验脚本，并确认新增资源被主文档索引。

**失败信号**

- 只写计划不落文件。
- 新增文件未被 `SKILL.md` 索引。
- 脚本不能运行或硬编码某项目路径。

## Case 9：证据不足的设计冲突必须确认

**用户提示**

> 两份规则分别要求保留旧接口兼容和移除旧接口；它们都像仍有效，但仓库中没有当前设计决定。帮我清理过期规则。

**期望结果**

- 不编辑规则，也不擅自选择任一版本。
- 向用户明确说明冲突、各候选取舍的影响，并询问应保留兼容还是移除旧接口。

**失败信号**

- 删除任一版本。
- 保留两份并列规则。
- 未经确认猜测折中方案。

## Case 10：AGENTS 报告式治理与单一权威源
**用户提示**
> 两份项目配置和 `AGENTS.md` 都写了 RCON 信息。先按报告式处理，不要删掉我明确要求保留的密码，并确保运行时只有一个权威源。
**期望结果**

- 先列出路径、行号、`LastWriteTime`、消费者和非敏感内容差异；密码只报告存在性，不回显。
- 选择一个运行配置作为 canonical source，明确其它文件是同步副本或非权威记录；移除脚本对旧路径和硬编码密码的隐式 fallback。
- 保留用户明确要求保留的 `AGENTS.md` 密码行，但不把它复制进全局 skill；修改前后都检查引用是否收敛。
- 项目明确不用 Git 时不执行其它 Git 操作；若用户只要求清理误跟踪，则只处理点名文件，保留磁盘文件，不执行服务器目录的全库清理。
**失败信号**

- 未经用户选择删除 `AGENTS.md` 规则或凭据。
- 让脚本继续按 `.claude`、`.codex` 等旧路径择一读取。
- 把本地端口、密码或项目路径写进全局 `agents-updater`。

## Case 11：严格 profile 与兼容 profile
**用户提示**
> 新建一个可复用 skill，同时把已有 skillshare skill 的重复说明降噪。
**期望结果**

- 新 skill 使用 `strict-skill`：读取 `skill-creator`，采用最小 frontmatter、渐进披露和可执行验证。
- 旧 skill 使用 `compat-skillshare`：只删重复/过期说明，保留同步入口和已有行为，不做无关重写。
- 两者分别运行相应校验，并在报告中区分全局、项目和不沉淀内容。
**失败信号**

- 用同一套批量格式覆盖所有旧 skill。
- 只写计划不运行校验，或把项目事实写进全局 skill。

## Case 12：模型候选的视觉近重复不能仅按文件摘要去重

**用户提示**

> 上一批模型里有两个不同路径的 `.bbmodel`，内部名称、纹理、动画和层级基本相同，只是文件摘要不同；以后打开候选前先避免把它们当成两个独立选择。

**期望结果**

- 将规则落到项目的模型审查 skill/reference，不写入全局 skill 的项目路径、模型名称或一次性批次记录。
- 明确区分精确内容去重与视觉/语义近重复复核；完整文件 SHA-256、`bundle_id` 或 geometry-only 指纹不能替代近重复判断。
- 要求可见打开前先做 dry-run 近重复分组，列出路径和证据；同组默认作为一个用户选择，只有用户明确要求才同时打开变体。
- 保留精确 `bundle_id + source_lock` 的隔离门禁，不按显示名直接删除或逐出。
- 修改保持兼容 profile 的最小范围，并运行相关 skill 审计或轻量验证。

**失败信号**

- 只在全局 `agents-updater` 中记录项目模型路径或具体文件名。
- 把不同完整摘要直接当成不同视觉模型，或把相同几何直接当成可删除证据。
- 为一次批次新增不可复用的模型名单、临时脚本或 fallback 路径。
